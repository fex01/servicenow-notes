# Coverage and human guidance

1. Run `python scripts/inventory.py SOURCE... --output INVENTORY.json`; use bundled Python with pypdf for PDFs. Existing output is protected unless `--force` is explicitly passed. Inventory contains headings, hashes, locations and per-page visual-review flags, not body text; treat headings as potentially sensitive course material.
2. Run `python scripts/coverage.py init INVENTORY.json COVERAGE.json`. This creates one unreviewed `candidate` per detected heading. IDs identify source path, line and title; the source hash supports change detection, but moved headings need reconciliation. PDF sources start with an unresolved source-review item; headings and interactive or screenshot-only content are not automatically discovered. Inspect visually, add missing lesson and lab entries manually, and mark the source-review item excluded with a reason after completing that review.
3. Review each relevant lesson and lab. Set `status` to `mapped` with `target_anchor`, `excluded` with `reason`, or `unresolved` with a reason. Use `prerequisites` for other item IDs; mark optional labs with `optional: true`. If a required lab depends on optional setup, document an alternative in the notes and record it in `dependency_alternatives` as `{ "<prerequisite-id>": "<brief alternative>" }` without deleting the dependency. Source-to-notes links reflect a review decision, not proof of semantic equivalence.
4. Run `python scripts/coverage.py check COVERAGE.json NOTES.md`. Resolve missing anchors, missing/optional prerequisites and unreviewed entries; retain explicit TODOs for material that cannot be checked. Review config values, scripts, screenshots and final notes against the actual source independently of this mechanical check.
5. For a missing source, identify the exact page, file or authorized login needed. For instance validation, list required role, navigation, exact data/setup, action, positive/negative expected outcomes and safe cleanup. Never ask for a password or claim a lab was tested without executing it. Continue work that does not depend on missing input.

Keep working manifests in the requested workspace or a temporary directory. Do not commit course content, credentials or session data by default.
